# Object Recognition with Landmark Detection and Camera Calibration (OpenCV, Python)

Everything needed to run the assignment is in this folder. No camera or photographs are required to start. The sample images are generated by the code.

## Files

| File | Purpose |
|---|---|
| `run_demo.py` | Runs the whole experiment in one command (recommended first step) |
| `make_sample_materials.py` | Generates the reference, query and chessboard images |
| `calibrate_webcam.py` | Chessboard calibration: estimates the camera matrix and distortion coefficients |
| `object_recognition_calibration.py` | Main program: SIFT, KNN matching, Lowe's ratio test, undistortion, recognition, optional homography |
| `sample_materials/` | Generated images and the calibration file (created by the scripts) |
| `Object_Recognition_Assignment_Answers.docx` | Answer document with the observation table and questions |

## 1. Setup (once)

You need Python 3.8 or newer.

```
pip install opencv-contrib-python numpy
```

If you have also installed `opencv-python` before, remove it first to avoid conflicts:

```
pip uninstall -y opencv-python
pip install opencv-contrib-python numpy
```

On Windows use `python` in place of `python3`. On macOS or Linux, `python3` may be needed.

## 2. Quick start (no camera needed)

Open a terminal in this folder and run:

```
python run_demo.py
```

This generates the sample images, calibrates the simulated camera and runs all test cases. Each test is run twice, with the approximate matrix and with the measured matrix. The results are written to `demo_results/`, and one row per run is added to `demo_results/observations.csv`. The run takes about 30 seconds.

## 3. Run the steps yourself

The steps below show what each part of the assignment does, for when you want to run them one at a time.

**Generate the sample images:**
```
python make_sample_materials.py
```

**Calibrate the camera from chessboard images** (the sample set is used here; use `--capture` for your webcam):
```
python calibrate_webcam.py --images sample_materials/chessboard --rows 6 --cols 9 --square 25 --out sample_materials/camera_calib.npz
```

**Recognize the object with the approximate matrix:**
```
python object_recognition_calibration.py --reference sample_materials/reference.jpg --query sample_materials/query_similar_viewpoint.jpg --label "similar viewpoint"
```

**Recognize the object with the measured matrix and the homography extension:**
```
python object_recognition_calibration.py --reference sample_materials/reference.jpg --query sample_materials/query_different_viewpoint.jpg --calib sample_materials/camera_calib.npz --homography --label "different viewpoint"
```

**Test a different object:**
```
python object_recognition_calibration.py --reference sample_materials/reference.jpg --query sample_materials/query_different_object.jpg --calib sample_materials/camera_calib.npz --label "different object"
```

## 4. Using your own object and camera

1. Take a reference photo of your object (flat, front-on, good light), and save it as `reference.jpg`.
2. Take query photos of the same object from other angles, and of a different object. Save them as `query1.jpg`, `query2.jpg`, and so on.
3. Calibrate your camera. Print a chessboard (7 x 10 squares gives 6 x 9 inner corners, so use `--rows 6 --cols 9`), then run:
   ```
   python calibrate_webcam.py --capture --rows 6 --cols 9 --square 25
   ```
   Hold the board at different distances, angles and positions across the whole frame. Press SPACE for each good frame (15 to 20 frames), then ESC. An RMS error below about 1 pixel is good.
4. Run the recognition program with `--calib camera_calib.npz`, as in section 3.

Use `--label` to name each run. Every run appends a row to `outputs/observations.csv`, which you can copy into the observation table.

## 5. Output files

Each run of `object_recognition_calibration.py` saves these files to its output folder (`outputs/` by default):

- `undistorted_query.jpg` (the query after `cv2.undistort`)
- `landmark_matches.jpg` (the matching image, with the result written on it)
- `keypoints_reference.jpg` and `keypoints_query_undistorted.jpg` (the detected landmarks)
- `object_location.jpg` (only with `--homography`)
- `results.txt` (the calibration matrix, keypoint counts and match counts for that run)
- `observations.csv` (one row per run)

Each new run overwrites the image files, so copy them out after each test you want to keep. The CSV file keeps the history.

## 6. Expected results with the sample materials

These are the results from the sample set. Small differences are possible between OpenCV versions.

| Test | Reference keypoints | Query keypoints (after undistortion) | Good matches (approximate K) | Good matches (measured K) | Result |
|---|---|---|---|---|---|
| Same object, similar viewpoint | 1064 | 1162 | 526 | 480 | OBJECT RECOGNIZED |
| Same object, different viewpoint | 1064 | 1044 | 421 | 408 | OBJECT RECOGNIZED |
| Different object | 1064 | 1424 | 41 | 25 | OBJECT NOT RECOGNIZED |

The measured calibration recovered the simulated camera closely. The true values were k1 = -0.25 and k2 = 0.08. The recovered values were k1 = -0.248 and k2 = 0.077, and the focal length is about 501 px against a true value of 500 px.

With the approximate matrix, the distortion is assumed to be zero, so undistortion does not change the image. The before and after counts are therefore identical. With the measured matrix, undistortion is accurate, but the good-match count drops slightly. This is a finding in its own right, and the answer document discusses it.

## 7. Thresholds and why they are set as they are

- `LOWE_RATIO = 0.75`: a match is kept only if its best distance is less than 75% of the second-best distance.
- `MIN_GOOD_MATCHES = 50`: the recognition decision. The same object gives 400 to 500 good matches on the samples, and the different object gives about 40. The threshold sits between them. For real photographs the numbers will be lower, so **tune this value on your own images** and record the change in your report.
- `MIN_HOMOGRAPHY_INLIERS = 20`: the minimum RANSAC inliers needed to accept the object's location.

All three are constants at the top of `object_recognition_calibration.py`.

## 8. Troubleshooting

- **`AttributeError: module 'cv2' has no attribute 'SIFT_create'`**: install `opencv-contrib-python`, then uninstall `opencv-python` if both are present.
- **`Could not open webcam`**: try another index with `--camera 1` (or `2`). Close other programs that use the camera.
- **`OpenCV could not read the image`**: check the file path and name. Paths with spaces need quotes.
- **`Chessboard not found` for many images**: the board must be fully visible, flat and evenly lit. Check that `--rows` and `--cols` count the inner corners, not the squares.
- **`Only N usable images`**: capture more chessboard frames, at least 10 to 15.
- **Result says OBJECT NOT RECOGNIZED for the same object**: the object may have too little texture, or the query may be blurred or too dark. Try a better reference photo, or lower `MIN_GOOD_MATCHES` after checking the counts in `results.txt`.
- **Few keypoints on a plain object**: SIFT needs texture. Choose an object with printed text, logos or colour patterns.
